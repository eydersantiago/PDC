# Examen del 28 de octubre de 2026: Sistema bancario

Parte práctica del parcial de FPOO-01 (miércoles 28-10, 8:00-11:00, 20 % de la nota). Cada estudiante implementa el Sistema bancario desde cero en C++ con ADACEEN, a partir de las HU-1 a HU-5 y el diagrama de clases. La entrega puede ir hasta el domingo.

## La noche anterior

1. Desplegar el backend (rama `feature/azure-config-observability`). El primer arranque fija el tema «Parcial: Sistema bancario» del docente de las cuentas nuevas y carga el enunciado en el RAG.
2. Crear y subir el repositorio público `eydersantiago/sistema-bancario-fpoo` (README, HU, diagrama, PDF, `Makefile`, tarea de entrega).
3. En Cloud Shell, VM de editores grande para unos 40 estudiantes (e2-standard-16; si la cuota de CPU no alcanza junto con la V100, el script elige e2-highmem-8 o e2-highmem-4, que tienen la misma memoria o la mitad) y startup-script nuevo en las GPU (2 pedidos a la vez si el modelo cabe):

   ```bash
   cd ~/PDC && git pull && bash deploy/gcp/preparar-examen.sh antes
   ```

4. Confirmar que la V100 esté en modo clase (estándar): `preparar-examen.sh` avisa si está en Spot. Si lo está, usa `ADACEEN-GPU.bat`, opción C.

## A las 7:00


## Durante el examen

- **Entrada:** con Google institucional entran sin código. Con Gmail les pide el código de 7 dígitos; si su cuenta de la lista nunca entró, quedan unidos solos. Si sale «Tu docente tiene que aprobar este correo», el docente lo aprueba en «Usuarios» o el estudiante entra con su correo institucional.
  - Probado el 28-10 en PostgreSQL 16 (`tests/routes/primer-ingreso-institucional.test.ts`): quien está en la lista con su correo institucional entra la primera vez a esa misma cuenta, con su docente, el parcial en Inicio y VS Code. Quien quedó en la lista con un Gmail o Hotmail de Campus y llega con el institucional entra a una cuenta nueva con el docente de las cuentas nuevas: puede hacer el examen, pero queda duplicado y se une después.
- **Tutor lento o «no disponible»:** si `/api/health` dice `queue_suspect: true`, la cola no está llegando a la GPU. El worker reconecta solo en máximo 4 min. Si sigue, reinicia el worker:
  `gcloud compute ssh adaceen-worker-v100 --zone=us-central1-a --tunnel-through-iap --command='sudo systemctl restart adaceen-worker'`.
- **Sin GPU** (`model_workers_alive: 0`): `bash deploy/clase.sh iniciar` otra vez (prueba V100 → A100 → L4).
- **Entrega:** *Terminal → Run Task… → «Preparar entrega (.zip)»*, clic derecho sobre `entrega-<usuario>-sistema-bancario.zip` → **Download**, y se sube al Campus.
- **Respaldo de todas las entregas** (Cloud Shell, se puede correr a mitad del examen y al final, antes de `clase.sh terminar`; solo lee):

  ```bash
  cd ~/PDC && git pull && bash deploy/gcp/recoger-entregas.sh
  cloudshell download ~/entregas-sistema-bancario-fpoo-<fecha>.zip
  ```

  Un zip con `entregas/<login>/` (el código de cada editor, aunque no haya armado su zip) y `entregas/LISTA.csv` (login, nombre, correo, archivos .cpp/.h, último cambio y si armó su zip). No sigue enlaces simbólicos, no saca el `sessionId` y en la VM queda 0600 y se borra al terminar.

## Otra cuenta de Google Cloud (respaldo de créditos)

La GPU y la VM de editores hablan con Azure por la cola y el relay, no por el proyecto. Cualquier proyecto con los mismos secretos atiende igual.

1. En la cuenta actual (Cloud Shell): `bash deploy/gcp/exportar-cuenta.sh` → `~/adaceen-cuenta.env` (600, con secretos). Descárgalo y guárdalo fuera del repositorio.
2. En la cuenta nueva: crea un proyecto con facturación vinculada. Si es una prueba gratuita, pásala a cuenta de pago (los créditos se conservan), porque sin eso no hay GPU. Después pide la cuota «GPUs (all regions)» = 1.
3. Sube el archivo a su Cloud Shell, clona PDC y corre:
   `PROYECTO=<id-nuevo> bash deploy/gcp/montar-cuenta-nueva.sh ~/adaceen-cuenta.env v100` (o `l4`, `t4`, `cpu`).
4. Apaga la VM de editores de la cuenta vieja (solo una a la vez) y enciende con `PROYECTO=<id-nuevo> bash deploy/clase.sh iniciar`. En `ADACEEN-GPU.bat`, cambia el proyecto.
