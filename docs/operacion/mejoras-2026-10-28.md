## Desplegar

1. Encender el aviso (monitor del docente con la cuenta de administrador) si hay estudiantes conectados. A la hora del despliegue no debería haber nadie.
2. Push de la rama a `feature/azure-config-observability` (fast-forward, sin `--force`). El flujo de GitHub Actions corre `npm run build` y `npm test` y despliega.
3. Verificar: `curl -sS $BACKEND/api/health` trae `maintenance`, `gpu_autostart` y `workspace_backup`; `/empezar` muestra el horario si `GPU_SCHEDULE` está en Azure.
4. En Cloud Shell (la cuenta dueña del proyecto de las VMs), con la rama ya en GitHub:

   ```bash
   cd ~/PDC && git pull
   bash deploy/gcp/respaldos.sh activar
   RG=rg-adaceen-azure bash deploy/gcp/horario-gpu.sh activar
   ```

   `respaldos.sh activar` necesita la VM de editores apagada la primera vez (cambia el alcance de su cuenta de servicio). `horario-gpu.sh activar` con `RG` y `az` carga en Azure `GPU_SCHEDULE=06:00-23:00`, `GPU_SCHEDULE_TZ=America/Bogota` y `GPU_AUTOSTART=on` (reinicia el App Service, ~1 min) y revisa que `CLASS_GPU_VMS` incluya la GPU; sin `az`, imprime el comando. Si avisa que la cuenta `adaceen-autoencendido` no tiene permiso sobre la GPU: `GPUS=adaceen-worker bash deploy/gcp/crear-cuenta-autoencendido.sh --sin-clave`.
5. `bash deploy/gcp/respaldos.sh estado` y `bash deploy/gcp/horario-gpu.sh estado`.
6. Apagar el aviso.
7. Publicar el horario en el Campus (después del paso 4: el encendido de noche depende de él).

## Volver atrás

- Backend: el rollback de siempre ([despliegue, sección 8](despliegue.md#8-rollback)). El esquema de la base no cambia: los ajustes nuevos viven en `app_settings` (`maintenance_notice`, `workspace_backup_last`).
- Horario: `bash deploy/gcp/horario-gpu.sh desactivar` y `GPU_AUTOSTART=off` en Azure.
- Respaldos: `bash deploy/gcp/respaldos.sh desactivar` (conserva el bucket y las instantáneas).
- Ingreso institucional: es código del backend; vuelve con el rollback.
